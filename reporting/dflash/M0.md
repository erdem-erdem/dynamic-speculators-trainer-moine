# M0: Headline: base vs static LoRA vs generator

- **Tier:** 1
- **Status:** done (2026-11-09): validation, untouched test split, out-of-distribution set
- **Plan entry:** `dflash_port/EXPERIMENT_MATRIX.md` (M0)
- **Evaluation protocol:** [README](README.md#evaluation-protocol)

## What is tested

Does the per-prompt LoRA generator beat both the released DFlash drafter and a matched static LoRA? The generator reads each prompt's target summary and writes a rank-32 LoRA for the drafter's q/k/v/o projections in all 5 draft layers; the static LoRA is one learned LoRA for every prompt.

## Methodology

- Three matched arms on the 4K pool (1,000 rows per category from `*-00000`), 1,500 updates, seed 42. Only the arm differs (EAGLE-3 GEN-009/010 structure study).
  - **Base:** the released `z-lab/Qwen3-8B-DFlash-b16@9b41424b`, unmodified (base-only eval).
  - **Static LoRA:** rank 32, α 64, q/k/v/o × 5 layers (4.26M parameters).
  - **Generator:** 2.20B parameters (decoder 512, heads per module), one LoRA per row (round 6), 18 rows per update.
- Loss: CE + D-PACE (α 0.5, γ 4); anchor density 1/16.
- Validation: the 200 fixed rows (50 per category), fixed anchors (seed 0), every 250 updates. Offline evaluation of the final checkpoint: reproduction, M4 coefficients, M7 donors, K=4 view, D13, D14.

## Measurements

Teacher-forced, offline: **score** = `full_acc` (fraction of anchors whose whole 15-token block is accepted, pooled), **τ** = `eal` (expected accept length per block). Per category: acc / τ.

## Results

### Headline (validation, final checkpoints, training coefficient s = 2)

| Arm | score | τ | Δ score vs base | Δ τ vs base |
|---|---|---|---|---|
| Base | 0.5246 | 7.108 | | |
| Static LoRA | **0.5304** | **7.255** | +0.0058 | +0.147 |
| Generator | 0.5220 | 7.129 | −0.0026 | +0.021 |
| Generator at s = 1 (half the generated ΔW) | 0.5289 | 7.224 | +0.0043 | +0.116 |

1. **The generator does not beat the static LoRA at 4K.** Its validation peaks at update 250 (0.5289, τ 7.238), then falls steadily to 0.5220 at 1,500, below base in score. The static LoRA rises to 0.5300 by update 250 and stays flat (0.5304 at 1,500).
2. **The generator overfits.** Its training loss keeps falling (0.474 → 0.450 over the six 250-update windows) while validation falls; the static LoRA's training loss is flat (≈ 0.47). 1,500 updates × 18 rows ≈ 6.75 passes over the 4K rows, for a 2.2B-parameter generator that writes one LoRA per row.
3. **The generator is dynamic, but the dynamism does not help here.** D13 on the 200 generated LoRAs: cosine within category 0.925 vs across 0.667 (gap 0.259), dyn_ratio 0.268, effective rank 3.60, centroid accuracy 0.965: the LoRAs clearly depend on the prompt and its category (at 100 updates, P2: dyn_ratio 0.0005). Yet M7: at s = 2, conditioning on the **wrong** rows scores higher than the row's own (cross-category 0.5245, fixed donor 0.5240, correct 0.5220).
4. **M4: the generated updates are too large.** Halving them (s = 1) brings the generator back to 0.5289 (its update-250 level); s = 0.5 gives 0.5285; s = 4 and 8 collapse (0.4785, 0.2161). The static LoRA is best at its training scale (s = 2: 0.5304; s = 1: 0.5300). A per-row oracle over s gains +0.06 to +0.10 τ over the best fixed s in each category, for both arms.
5. **Cost (D14, H100, bf16):** 4.52 ms per generator call, 6.29 ms for 8 batched cohorts, 0.68 ms to merge ΔW (20 modules, rank 32, 8.5 MB of factors per LoRA).

### Comparison with EAGLE-3 (descriptive only)

EAGLE-3 GEN-012 (DeepSeek ttt7 drafter, 4K, 1,500 updates, q/k/v/o generator) reported +6.6 to +16 % tok/s and higher acceptance in serving, with no static control. Its offline validation is not comparable: the EAGLE-3 records used different validation rows, and GEN-001 notes that subset 00000's validation rows were also seen in training. Here the validation rows are disjoint from all training rows (checked by prompt hash and id), and the static control is matched. Different drafter family, metric and runs: no conclusion is drawn from the gap.

## Notes

- Single seed (42), as EAGLE-3 (whose serving records show about 5 % run-to-run drift). There are no seed repeats here, so the seed-to-seed spread of these offline scores is unknown; differences of a few thousandths between arms should not be read as established. The generator's decline over training (−0.007 from its peak) appears in every category, and the M4 / M7 patterns are consistent across categories.
- The offline reproduction of the generator differs from training's final validation by 5e-5 (GPU kernels, not bitwise); the static LoRA reproduces bit-exactly.
- Offline evaluations use the final (update-1500) checkpoint; checkpoints exist at 500 / 1000 / 1500 only, so the update-250 peak cannot be re-evaluated.
- Published: `erdem-erdem/dyn-spec-dflash-m0-generator-attn-r32-4k-1500` @ `f6bdfb11` (13.2 GB: checkpoint with optimizer state, results, offline evals, provenance) and `erdem-erdem/dyn-spec-dflash-m0-static-lora-attn-r32-4k-1500` @ `f8739c68`.
- Open (not decided here): how to train the generator on 4K without overfitting (fewer updates, regularisation, smaller generator) is not part of the mirrored protocol; the capacity ablations (M2 rank, M3 width) and the 24K pool bear on it.
