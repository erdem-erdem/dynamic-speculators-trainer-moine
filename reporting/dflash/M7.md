## What is tested

Does the generator use the content of its conditioning? Each validation row's LoRA is generated from (a) its own prompt (`correct`), (b) one fixed set of unseen rows for every row (`fixed`), or (c) an unseen row of another category (`cross_category`, the next category in sorted order). If the row's own prompt matters, `correct` should score highest.

## Methodology

Offline, on the final M0 generator checkpoint, for every M4 coefficient. Donor rows come from the `*-00002` validation splits: never trained on, never evaluated. `fixed` = the first row by primary id of the first donor subset (one LoRA for every row); `cross_category` = a seeded random unseen row of the next category. Same evaluation rows and anchors as every other variant. (EAGLE-3 record: correct > cross-category by +11 pp acceptance on math in serving, `ablations_v4`.)

## Measurements

score / τ per donor and coefficient; per category at s = 2.

- **At the training scale (s = 2), the row's own conditioning is the worst of the three** (correct 0.5220 < fixed 0.5240 < cross-category 0.5245). At s = 1 and 0.5 the three are within 0.001 of each other, correct marginally highest.
- At s = 4 and 8 the gap widens in the same direction (s = 8: correct 0.2161, cross-category 0.2686, fixed 0.2954): the LoRA generated from the row itself is the most harmful when amplified.
- So at 4K / 1,500 updates the generator's conditioning effect is real (the LoRAs differ by prompt, D13) but not beneficial: the prompt-specific part of ΔW hurts the row it was made for. This is the overfitting seen in M0's training curves.
