## 1. Drafter improvement (static first; every finding transfers to the generator)

### 1.1 Fix the objective (highest priority)
Training lowers a loss that does not track τ. Until that changes, both static and generator arms optimize the wrong thing. Every run below is a 600-update short run with the PERTURB24K harness (≈ 30–40 min, static rank 32 on attention, 24K rows, from base). Each reports τ *and* its own held-out loss, so we can see whether the two now move together.

| ID | Variant | Why |
|---|---|---|
| R1 | KL without D-PACE weights (uniform positions) | Isolates whether the D-PACE weights, computed from KL instead of the CE confidence upstream documents, cause the loss/τ mismatch |
| R2 | D-PACE weights from a CE confidence (upstream's definition), KL per-position loss | Restores upstream's documented weighting |
| R3 | **τ-aligned loss (D3):** maximize E[accepted] = Σₖ Πⱼ≤ₖ pⱼ(target argmax), as a log or a surrogate | Weights exactly the first failing slot; penalizes breaking accepted prefixes (the adapters' main loss in ANALYSIS24K step 1) |
| R4 | Early-slot weighting: exponential decay on slot index, γ ∈ {0.8, 0.9} (EAGLE-3-like; not the γ7 that failed at 4K) | Slots 1–4 decide τ but move least (F5) |
| R5 | Prefix-protection term: hinge or KL anchor to base on slots the base already gets right in an all-correct prefix | Targets the 4:5 break:fix ratio |
| R6 | Greedy-path labels: train only on positions still on the target's greedy path | 15.6% of misses are off-path; their labels teach nothing τ-relevant |

Then: take the best one or two to a full 24K 3-epoch static (≈ 3 h), and only then to the generator.
- **Decision rule:** a variant passes if held-out loss and τ move in the same direction *and* τ ≥ the KL static at 600 updates.

### 1.2 Data and labels
- **R7: 100K static (M11, static only first).** Data has been the strongest lever: +0.055 τ from 10K-math to 24K mixed, against +0.022 for the generator.
  - The store is ≈ 9 TB at the 24K rate; 33 TB are free. Online extraction is the alternative.
  - Run it with the R1–R6 winner.
- **R8: greedy-path / tie-aware evaluation** (ANALYSIS24K suggestion 5). Re-score existing arms with labels on the target's greedy path, with bf16 ties counted as matches. It removes ≈ 20% of "misses" that are not drafter errors, and makes ±0.02 τ differences easier to read.
- **R9: greedy-regenerated responses** for a 6K subset (vLLM `responses` mode, temperature 0) as training data.
  - Tests whether sampled-response labels cost τ under greedy verification.
  - Check against what serving will actually use (greedy or sampled acceptance) before investing.

### 1.3 Capacity and placement (low priority; PERTURB24K says it is not the limit)
- **R10:** full fine-tune with an LR sweep (10⁻⁶ / 10⁻⁵ / 5·10⁻⁵, PERTURB D5) at 3 epochs. The 600-update result may still be under-trained.
- **R11:** static `fc` adapter (largest first-order gain, the only module sensitive to random updates). D4 tested `fc` only inside the generator.
- **R12:** a trust-region or line-searched static update (PERTURB "control the step"). Speculative; only after R1–R6.

### 1.4 Noise floor and reality
- **R13: three seeds** for the 24K static (KL) and the 24K generator (KL), ≈ 4 × 3 h. The +0.022 τ margin is the size of the drift seen elsewhere, so nothing below is readable without this.
- **R14: serving check (P5)** for base vs static on vLLM: does +0.2 τ (≈ 2.7%) become tok/s? Also the per-request generator overhead (≈ 4.2 ms + 0.7 ms merge) and batching.

## 2. The generator

### 2.1 Correction: the EAGLE-3 arm did not use small generators

Parameter counts reproduced exactly from the recorded EAGLE-3 numbers (`docs/experiments/eagle3_generator_architecture.md:166-177`). Calculator: `$CLAUDE_JOB_DIR/tmp/calc.py`.

| Arm | Config | Generator params | Static LoRA control |
|---|---|---|---|
| EAGLE-3 (1 layer, input 12,288) | v/o, decoder 512 (the historical baseline, GEN-010/012) | **293M** | ≈ 3M |
| | q/k/v/o, decoder 512 | 646M | |
| | all modules | 1.45B | |
| | v/o, decoder 256 (smallest ever specified) | 150M | |
| DFlash (5 layers, input 20,480) | q/k/v/o, decoder 512 (M0) | 2.20B | 4.26M |
| | decoder 256 (10K-math, 24K) | 1.11B | |
| | per-type heads (D3) | 0.45B | |

- **The "few million" figure is the static LoRA.** notes/04 §2.3 reads: "gen has 293M vs about 3M params".
- **Every generator in both arms is the same dense full-factor hypernetwork.** No basis mixing, no factorized heads, no chunking exists in `src/`.
- **Small generators are new territory,** not something to port from EAGLE-3. The EAGLE-3 structure study (GEN-009) did find width and depth unimportant ("weight count itself is not the success metric"), as M3 / D3 did here.

### 2.2 Why it is large, and what that implies for small designs
```
summary 20,480 → encoder (10.6M) → condition (≤ 0.04M) → decoder trunk (0.3–1.1M)
  → per-module heads A: Linear(W → r·in), B: Linear(W → out·r)   = (W+1) × 4.26M (attention, r32, 5 layers)
```
- **The heads hold ≈ 99% of the parameters.** Every generated LoRA lies in a (W+1)-dimensional affine space of factors.
- **The head biases are a static LoRA.** The A bias is kaiming-initialised and B starts at zero, so at init the generator *is* a static LoRA, and the bias stays an un-conditioned (static) component throughout training: generator = static + (part linear in the decoder code z), through ΔW = (B₀ + B_z)(A₀ + A_z).
  - So the 24K generator vs static comparison is already "static + residual".
  - A small generator only needs a small W.
- **The 24K generator uses ≈ 2.5 effective dimensions** of ΔW (D13). A code of 4–8 dimensions per module is plenty to represent what it learned.
- **At small sizes the encoder dominates:** Linear(20,481 → 512) is 10.6M. Any generator under ≈ 20M needs a smaller encoder: hidden 64 (1.3M), a fixed PCA / random projection (0 trainable), or a single layer's 4,096 features.
- **per_type shares the bias across layers.** That ties the static part across all 5 layers. D3 saw no loss at 4K, but at small W a per-module bias (4.26M, a few lines of code) is the safer choice.

### 2.3 What "learns as I want" should mean (acceptance criteria)

A generator configuration is "working" only if all of these hold, measured on the same rows with paired CIs:

1. **Beats its matched static** at equal trainable parameters, equal loss, data and schedule (L1).
2. **Uses its condition:**
   - its own LoRA > the mean-condition LoRA > a shuffled same-category LoRA > an other-category LoRA (L2);
   - "own > mean" is the honest test of per-prompt value. The existing M7 "fixed donor" is one row's LoRA, a noisier stand-in.
3. **Gains more than routing does:** own > the category-centroid LoRA (the average generated ΔW per category). Otherwise a 4-LoRA router does the same job (L3).
4. **Does not collapse:** effective rank > 1 and dyn_ratio > 0.05, tracked over training, not only at the end (L4).
5. **Holds OOD:** OOD ≥ matched static (L5).
6. **Scales:** the margin over static grows or holds from 24K to 100K (L6).

Today's 24K generator meets L1 (barely, one seed), L4 and L5. L2 is only partially known (M7). L3 and L6 are unknown.

### 2.5 Phase G1: small generators, parameter-matched against static LoRAs

- **Equal targets:** attention q/k/v/o, all 5 layers. Equal rank of the *emitted* LoRA where possible.
- **Equal recipe:** the R1–R6 winner, or KL if 1.1 is not done; 24K mixed, 3 epochs.

### 2.6 Phase G2: can it learn at all? (positive controls)
A small generator that matches static on 24K could mean "nothing to learn" or "cannot learn". These separate the two.

- **R24: factor distillation (no new data).**
  - Train per-category static LoRAs (A1; 4 runs on the 24K category splits).
  - Train a small generator to regress them from the prompt summary with the existing `factor_loss` (`model.py:294`), then fine-tune through the drafter loss.
  - This tests whether the machinery and the conditioning can represent known, distinct LoRAs at 5–50M.
  - If A1 beats the global static, it also bounds what routing is worth (A1's original purpose).
- **R25: thinking vs non-thinking (B1).**
  - Regenerate ≈ 2K rows per category with Qwen3-8B `/think`.
  - The flag fully determines the response distribution, so one static LoRA must compromise.
  - Needs a store fill (≈ 1–2 TB). This is the realistic positive control; the generator must clearly beat static here.
- **R26: style or format tags (B2),** a synthetic control with a tunable payoff from dynamism. Use it only if R25 is ambiguous.

### 2.7 Phase G3: beyond prompt-level conditioning (if G1/G2 show the machinery works)
- **R27: block-level routing (G6).**
  - R22's coefficients are recomputed per DFlash block from the drafter's own context features: a mixture-of-LoRA-experts drafter.
  - Misses are local next-token near-misses (ANALYSIS24K), and the prompt is redundant, so this conditions on the quantity that is left.
  - Serving: per-block scales on a fixed rank-N·r LoRA; no merge.
- **R28: learned per-prompt scale** (D5 / M4 generalization; the per-row oracle coefficient was worth +0.06 to +0.10 τ per category at 24K).
  - Nearly free inside R21 / R22.
  - Check first whether the oracle gain is real or selection on noise: pick the coefficient on validation, score on test.
- **R29: response-so-far conditioning** (C4), regenerating every N tokens. Only with R27-style cheap mixing.
