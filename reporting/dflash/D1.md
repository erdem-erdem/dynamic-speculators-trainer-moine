## What is tested

Should the LoRA adapt how the drafter reads the target context, the denoising of the block, or both?

## Methodology

In DFlash attention, k_proj / v_proj process both the target-context features and the block's draft tokens. `adapter.kv_lora_path` applies the generated k/v LoRA to both paths (both ★ = M0), the context path only, or the block path only (`src/speculators/generator/drafters/dflash_attention.py`). q/o adapters are unchanged. Only `both` can be merged into the weights for vLLM serving. Everything else is as in M0 (attention targets, rank 32, 4K pool, 1,500 updates, seed 42, 200 fixed validation rows). Generators only: a static LoRA arm per path was not planned.

## Measurements

Acceptance per category and per position; offline M4 / M7 / D13 / D14 on the final checkpoint.

- **No path makes the correct donor beat a fixed ΔW at s = 2.** Correct is 0.0014–0.0016 below fixed for all three.
- **Nothing here argues against the mergeable `both` default.** The non-mergeable context-only and block-only variants buy no measurable acceptance.
