- **Tier:** 3
- **Status:** done (2026-11-10)
- **Plan entry:** `dflash_port/EXPERIMENT_MATRIX.md` (M6; design in round 7)
- **Evaluation protocol:** [README](README.md#evaluation-protocol)

## What is tested

How many conditioning rows does the generator need?

## Methodology

Generators trained and validated with K = 2, 4, 8 rows per generated LoRA (M0: K = 1), with 9 / 4 / 2 groups per update (18 / 16 / 16 rows; M0: 18) (`context.min_examples = max_examples = evaluation_sizes = K`, `optimization.episodes_per_update`). Everything else is as in M0 (attention targets, rank 32, 4K pool, 1,500 updates, seed 42, the same 200 validation rows).

A K-grouped validation number is compared only with numbers of the same grouping. Packing K rows changes the validation anchor draw: the P2 smoke found the static LoRA ≈ 0.01 lower at K = 4 with an identical ΔW. Two paired comparisons:
1. **At each arm's own K** (training validation): the M6 generator vs the base drafter at the same grouping (the run's update-0 validation, where the generated ΔW is 0) and the M0 static LoRA evaluated with the same grouping (`tier1_static_kgroups`: `--group-size 2 / 8`; K = 4 from the M0 static's continuity view).
2. **At K = 1** (one row per LoRA, as served; `run_arm --mode eval --group-size 1`): each M6 generator vs the M0 generator, static and base. For a K-trained generator one row is outside its trained K.

## Measurements

Acceptance per category for each K; offline M4 / M7 / D13 at the run's own K; M4 coefficients in the K = 1 view.

Findings (4K pool, one seed):

- **At its own K, every M6 generator overfits like M0.** Each peaks at update 250, between base and static (e.g. K = 8: base 0.5180 < peak 0.5213 < static 0.5232), and ends below base. The gap to the same-grouping static at the final checkpoint is −0.0053 to −0.0075, similar to M0's −0.0084.
- **In the K = 1 view the K-trained generators are slightly better than M0 at every coefficient.** At s = 1 they reach 0.5298–0.5301, matching the static at s = 1 (0.5300), the closest any generator has come. At s = 2 K = 4 and K = 8 end above base (0.5248, 0.5239) while M0 ends below (0.5220). All are still below the static at its best scale (0.5304). One row is outside a K-trained generator's trained K, so this view tests transfer, not the trained setting.
- **The correct donor is again no better than a fixed or cross-category ΔW at s = 2** (K = 8: −0.0019 vs fixed), so K-row conditioning does not add usable per-group information either.
- **With K rows the generated ΔW become almost purely category-determined**: within-category cosine ≥ 0.994, η² ≥ 0.975, centroid accuracy 1.0. Groups are drawn within each category's subset (`data.groups` per subset), so the generator maps each group to an almost fixed per-category ΔW. Row-specific variation shrinks as K grows (dyn_ratio 0.27 → 0.18).
- Training time falls with K (48 → 39 min) because there are fewer generator calls per update.
