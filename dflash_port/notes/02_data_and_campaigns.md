## 0. One-paragraph mental model

A **generator** G (hypernetwork, ~293M params for o/v-only, see `docs/experiments/eagle3_generator.md`) reads the **last-prompt-token hidden states** (3 aux layers x 4096 = 12288-d, BF16->float) of 1-8 query examples ("cohort"), and emits LoRA A/B factors for a **frozen** EAGLE-3 drafter's `o_proj`/`v_proj` (optionally q/k/v/o). Training is *direct*: the drafter is run on the cohort's saved target trajectories (teacher forcing, TTT=3, `lk_hybrid` loss), grads flow through the drafter into G (`engine.py:249-275`, `campaign_train.py`). The baseline ("matched static LoRA" = `fresh_lora`) is one ordinary rank-32 LoRA trained with the same loss/data/updates (`engine.initialize_direct`, `engine.py:160-174`: A kaiming-uniform, B zeros). Target hidden states for training are produced **online** by an external vLLM extractor replaying saved token ids (file backend, `hs_connectors`), not read from activation dumps (the older "hub" path that downloaded activation dumps is retired but still in code).

## 1. Data sources and preparation

### Datasets
- Source: `openeurollm/Nemotron-Post-Training-Dataset-v2-decontaminated`, configuration `default`, one HF split per category: `math`, `code`, `stem`, `chat` (`bank/config.py:25-31`; `examples/eagle3-lora/nemotron_100k_v1/math.yaml:261-267`; `bank_chat.yaml` has `split: chat`). - "Decontaminated" is only the upstream dataset's name. ### Hidden-state layers
- Qwen3-8B target (36 layers). Stored/extracted layer ids `[2, 18, 33, 36]`: three aux inputs (concatenated, 3x4096=12288) + final target state at index 36 (supervision for verifier logits). `bank/config.py:59-62`; vLLM flags `--target-layer-ids 2 18 33 --include-last-layer` (`scripts/train_attention_100k.py:289-300`, `campaign_online.md:58-68`). In `Corpus.microbatches` (`generator/data.py:293-302`): `hidden_states = states[:, :-1].flatten(1)`, `verifier_last_hidden_states = states[:, -1]`. Per-example full payload at 8192 tokens, 4 layers, BF16 ~ 256 MiB (`campaign_online.md:178-183`). Extraction sequence limit 8192 (+1 token vLLM needs -> `--max-model-len 8193`).
- Config guard: producer bank configs require exactly 4 layers (`CACHED_LAYER_COUNT`, `bank/config.py:10,216-233`); consumer (campaign) configs accept >= 2 (`MIN_CONSUMER_LAYER_COUNT`), must be sorted/unique. Drafter's own `target_layer_ids` must equal `layer_ids[:-1]` or Runtime raises (`generator/engine.py:96-97`).
- Dtype `bfloat16` enforced at extraction check (`online_activations.py:148`).

### Splits and leakage protections
- Fixed by seed-0 reservoir + deterministic subset slicing: `train_indices` / `validation_indices` persisted in `data.json`/manifest with ids (`bank/workflow.py:57-73`). `seed` for selection is `partition.seed=0`; frozen catalog is reused, never re-sampled (`eagle3_hub_preparation.md`: "Existing frozen catalogs are reused with their exact membership").
- Overlap checks: `Corpus.__init__` asserts all train+val indices across loaded subsets are disjoint (`generator/data.py:97-104`); `read_trajectories` asserts disjoint across ALL subsets of all four categories and checks counts per subset (1000/100) and id/order equality (`local_campaign.py:448-503`).
- Train/validation roles: campaign pretraining uses train rows of subsets `00000..scale-1`; validation = the 100 held-out rows of subset `00000` per category (`campaign.py:57-58`); adaptation `fresh_lora` uses subsets 00002-00005 train and their val (`campaign.py:71-72`). In full-data runs validation is the held-out rows of each `*-00000` (or a balanced `validation_examples_per_category` subsample, `validation_sampling.py:225-278`; 100K run: 250/category = 1,000 rows, 10 per subset; `attention_100k_2k_v1/README.md:"Settings and locations"`). Note: validation subset `00000` is *also a training subset* in every arm (its 1000 *train* rows are used; its 100 *validation* rows are held out) - same prompts distribution/subset, disjoint rows (`GEN-001-direct-data-scaling.md`: "their subset identity is represented in every training arm").
- Conditioning vs evaluation: in the campaign path there is **no separate "donor" set**. For every cohort the generator is conditioned on the *query examples' own prompt-end states* (`Corpus.context(cohort,...)`) and the drafter is then evaluated/trained on the *same* cohort (`engine.py:188-215 evaluate`: validation cohorts = groups of 4 consecutive shuffled validation rows `groups(indices, seed+9000, size, size)`; `engine.py:249-275 train_epoch`; `campaign_data.py:442-475 EpochSchedule`). Leakage from the answer is prevented because the conditioning vector is the hidden state at the *last prompt token* only (index `prompt_length-1`, `online_activations.py:151`, `data.py:36-67`); target is causal so it carries no response info. Prompt-only extraction for summaries uses tokens `input_ids[:prompt_length]` (`online_activations.py:113-115`). The legacy `Corpus.prepare` summary function takes `states[:prompt_length]` (`data.py:36-67`).
- The separate "donor" notion exists only for serving-time controls (v4 ablations): training-only donors (first 64 train rows/category) for fixed-donor / cross-category conditioning controls, and 50 tune + 50 test rows/category from held-out shard 00000 with seed 42 (`study_inputs.py:189-221, 320-355`, `generator_ablations_v4.md`). Tune/test/train overlap and cross-category identical prompts are rejected (`study_inputs.py:213-214, 266-271`).
- No cross-domain/text dedup (explicitly). Evaluation OOD sets (Red Hat speculator_benchmarks) are separate, handled by `export-validation --dataset RedHatAI/speculator_benchmarks` (`cli/generator.py:334-392`), out of this note's scope.

## 2. Campaign stages (two generations of orchestration exist)

### 2a. CURRENT: `speculators generator campaign` (direct-only, online activations)
Stages `prepare, pilot, pretraining, adaptation, all` (`cli/generator.py:107-136`; `campaign.py:539-608`; `online_campaign.py:259-336`). With `activation_source: vllm` `run_campaign` dispatches to `run_online_campaign` (`campaign.py:540-545`).
Jobs planned by `campaign.jobs()` (`campaign.py:44-77`) - **four runs**, all `lk_hybrid`, `objective=direct`:
- `scale-1-direct`, `scale-2-direct`, `scale-4-direct`: fresh generator pretraining on subsets `00000..scale-1` of every category = 4K/8K/16K train rows (`SCALES=(1,2,4)`, `campaign_config.py:14`). Validation: `*-00000` val rows (100/category), context size 4 only. Stage name "pretraining".
- `fresh_lora` (stage "adaptation"; the "matched static LoRA" arm): ONE ordinary LoRA, jointly trained across subsets 00002-00005 of all categories (16K rows), `adaptation_updates` updates (1000 in YAML). Earlier arms `fresh_generator`, `direct_1`, `direct_2` were retired (`ADAPTATION_ARMS=("fresh_lora",)`, `campaign.py:34`; `campaign_online.md:165-167`). Standalone matched version per scale: `speculators generator train-lora-baseline --scale {1,2,4}` -> `lora_baseline.py:286-307` (job copy with `arm=fresh_lora`, same subsets/updates as the generator).
- `direct` = generator G emits the LoRA per cohort from prompt states; `fresh_lora` = `generator is None` branch (`campaign_train.py:380`): drafter adapter params directly trainable. Both through same frozen drafter and loss.
- `prepare`: online: loads local trajectories + validates (no GPU, no vLLM) and returns `trajectory_examples` (`online_campaign.py:305-306`).
- `pilot`: 100 updates of `online-direct` and `online-fresh_lora` (subset 00000), incl. context-4 validation and first update with the longest trajectories (`EpochSchedule long_first`, `campaign_data.py:465-473`); must pass before full runs (`online_campaign.py:220-256, 307-323`). Hub-mode pilot additionally measured cold/warm cache x 4/8 download workers (retired path, `campaign.py:348-444`).
- Episode schedule: per update `episodes_per_update=4` episodes; each: pick category uniformly, subset uniformly, context size `randint(min_examples=1, max_examples=8)`, sample that many train rows without replacement; RNG `Random(seed + step*100003 + episode*1009)` -> index-addressable, resume-deterministic (`campaign_data.py:442-475`).
- Hard contract validators: `condition == "last"`, `evaluation_sizes == [4]`, `loss_fn == "lk_hybrid"`, `n_workers == 1`, `activation_local_dir is None`, `pretraining_subsets is None` (`campaign_config.py:104-138`).
- Outputs under `output_root/{pilot,pretraining,adaptation}/<label>/`: `checkpoint.pt` (model+optimizer+rng+history), `result.json`, `resolved_experiment.json`, `configuration.json`, `metrics.json`, `timing.json`, `train_command.txt`, `speculators.patch`, `provenance/` ; stage-level `results.json`, `comparison.{png,pdf,json}` (`campaign.py:447-503`); `campaign.json` manifest + `.campaign.lock`.
- Resume: completed matching runs are skipped; budget/output_root/validation interval changes keep the saved identity (`campaign_resume.py`, `compatible_campaign` `campaign_resume.py:333-343`, `campaign.py:276-305 campaign_identity`).

### 2b. LEGACY offline workflow: `speculators generator {prepare,conditioning,heatmap,pretrain,adaptation}` (`generator/workflow.py`, bank-based)
Bank reconstruction supervision era (bank warmup "retired" 2026-10-23 per `eagle3_generator.md`). Configured by `examples/eagle3-lora/generator_math.yaml` (`bank_config: bank_math_cloud.yaml`).
1. `prepare` (`workflow.py:27-38`): builds compact prompt-summary cache (`Corpus.prepare`, `data.py:138-217`).
2. `conditioning` (`workflow.py:110-131`): trains 3 fresh generators (`last`, `last_mean`, `projected`, `config.py:11-12`) on `math-00001` for `conditioning_epochs=5` epochs through the frozen drafter loss; winner by final-epoch score (first on ties), written to `conditioning/selection.json`. `last` won and is hard-coded since.
3. `heatmap` (`workflow.py:159-199`): 18 generators = 3 strides x 6 seed-groups (`Heatmap` defaults, `config.py:66-70`: strides `[10,20,30]`, seed_groups `[[42],[43],[44],[42,44],[43,42],[42,43,44]]`). Each trains for `pretraining_updates` (1000) with **L1 reconstruction of saved bank LoRA factors** (sample seed uniformly, then a snapshot of that seed, context 1-8). "Stride" = keep bank snapshots whose `collection_step % stride == 0` inside the seed-overlap window; seed group = which bank training seeds' snapshots are in the pool (`data.filter_snapshots`, `data.py:390-413`). Validation of generator output through frozen drafter at 250/500/750/1000 on `math-00000` val, contexts [1,4,8]. Exports `results.csv/json`, PNG/PDF heatmaps; winner -> `heatmap/selection.json`.
4. `pretrain` (`workflow.py:202-223`): multi-subset/multi-bank pretraining.
5. `adaptation` (`workflow.py:352-384`): 4 arms for exactly ONE epoch (`adaptation_epochs: Literal[1]`, `config.py:43`) on `math-00001`: `pretrained_generator` (heatmap winner), `fresh_generator`, `fresh_lora`, `transferred_lora` (seed-42 latest snapshot of math-00000). Offline-only; reads local hidden states via Hub/`BankFileTransfer`.
Retired design (bank-vs-direct paired campaign: six pretraining jobs 1/2/4 x bank/direct, 10K updates, bank L1 recon) is documented in `docs/experiments/eagle3_generator_campaign.md` and still reachable via `activation_source: hub` (default!, `campaign_config.py:66`).

### 2c. Other experiment drivers (all drafter-agnostic orchestration shells around `run_one`/`campaign_train.train_update`)
- `train-full-data` (`epoch_training.py`): exact epoch passes (`EpochSchedule`, `epoch_training.py:22-53`) over all subsets, capped by `--max-updates`, synchronous HF model-repo backups every `hub_upload_interval` steps (`backup_checkpoint`, `epoch_training.py:56-108`), `--arm generator|lora`. This is what `scripts/train_attention_100k.py` launches (`train_attention_100k.py:~330-346`).
- `train-structure` (`structure_study.py`): one fresh generator/static LoRA with GEN-001 protocol (module/architecture ablations: `structure_*` example dirs, `target_modules` q/k/v/o etc.).
- `prepare-experiments` + `train-experiment` (`study*.py`, v4 ablations): freeze membership (train subset 1, val subset 0: 1000 train, 50 tune, 50 test per category, `study_config.py:22-31`), objectives `prompt_lk|prompt_kl|prompt_ce|static_lora_lk`, and replay variants.
- **replay / prefix / feedback terminology (v4, `study_config.py:43-63`, `study_replay.py`, `generator_ablations_v4.md`)**: `replay` = target-assisted *on-policy rollouts*: collect up to 4 greedy speculative verification blocks per request using the current generator, verified against full target vocab, then immediately replay the proposed prefixes with gradients (supervises drafted positions, not saved responses). `conditioning: prompt` = LoRA from prompt states only (`replay_prompt_lk`); `conditioning: prefix` = regenerate LoRA from the latest *verified-prefix* states at verification-round boundaries (`replay_prefix_lk`); `feedback: true` adds a zero-initialised 3->64 projection fed `[last accepted/proposed ratio, EMA(0.9), observed flag]` (`replay_prefix_feedback_lk`). All three need a warm-start generator checkpoint at update 500 (`initial_checkpoint`, `initial_step`), +500 updates. Result: GEN-006 (`docs/experiments/results/GEN-006-replay-prefix-feedback.md`).
- **continuation** (`train-feedback`, `feedback_config.py`, `original_continuation.py`, `continuation_state.py`, `saved_response_feedback.py`, `online_feedback.py`): continue a *published* generator bundle (e.g. `azeeer/eagle3-generator-all24k-10ep-v1@bf3fb281..., step-00004000`) for +1000 updates on the 4K membership, restoring parent Adam moments/RNG by parameter name (`continuation_state.restore_parent_optimizer`). v1/v2 = online rollouts (historic; dropped); **v3** = "original pipeline continuation": same saved-response teacher-forced supervision, feedback computed from earlier prefix positions of the *same saved sequence* (first 64, next 64, rest) -> teacher-forced agreement proxy (`eagle3_original_pipeline_continuation_v3.md`, `saved_response_feedback.py`). No measurable benefit through step 500 (GEN-007).
- `online_feedback.py` / `study_replay.py` / `streaming.py`: differentiable *singleton* EAGLE-3 proposals with explicit causal KV cache (`streaming.py:1-15`), verifier from `target_verifier.py`; strongly EAGLE-3 (TTT) specific - see Q8.

## 3. LoRA bank

- What: per-category (math/code/stem/chat) x per-subset (`<cat>-0000{0..4}`; `00005` reserved for adaptation) x per-seed (`training.seeds` default [42,43,44]; cloud configs use [42]) **snapshots of a rank-32 LoRA fine-tune of the frozen EAGLE-3 drafter**, trained through the drafter's own loss (`kl_div`, TTT=3, noise_std 0.05) on that subset's 1000 train trajectories (`bank/workflow.py:403-489 train_config`, driven through the ordinary `speculators.train` trainer with `bank` extras `train/bank.py`).
- Recipe (`bank_math.yaml`, `bank_math_cloud.yaml:48-79`): LoRA r=32, alpha=64 (fixed, generator does not output alpha), dropout 0.05, target_modules exactly `[o_proj, v_proj]` (validator `bank/config.py:214-215`; "Bank v1 targets exactly o_proj and v_proj"); AdamW, warmup 1 epoch lr 1e-4 then `collect_epochs` (regular: 4, cloud: 1) at lr 1e-6, `loras_per_epoch: 10` snapshots evenly spaced (`ceil(j*S/K)`), `scheduler none`, token budget 8192. Each seed starts independently from the pretrained drafter; initialization = drafter's PEFT default (A random, B zero) - not from the generator.
- Used as: (legacy) reconstruction targets (L1 on A/B factors) for generator pretraining / heatmap; seed-42 latest snapshot as `transferred_lora` baseline (`workflow.py:359-366`). Read via `FactorCache` (`data.py:416-464`) which accepts either a plain `adapter_model.safetensors` path or a packed `{"file","tensor_keys"}` dict. **Not used by the current direct-only campaign** (`campaign_online.md:172`: "No bank download, catalog, saved LoRA snapshots, or reconstruction objective is used"). It is also the source of the "matched static LoRA" idea only conceptually; the actual `fresh_lora` baseline is trained directly, not taken from the bank.
- Hub: `azeeer/eagle3-qwen3-8b-lora-bank-r32-v1` release `b0002` (`bank/config.py:124-125`; `bank_*_cloud.yaml:banks_repo`), pinned bank commit `2305403f0f3b560fafb6c6d261c370ab3a95759d` (`campaign_config.py:65`, `generator_campaign.yaml:61-66`). Published via `lora-bank train-cloud/publish-bank` (`bank/cloud.py`, `bank/publication.py`) with per-seed `completion.json`, snapshots, provenance and recovery states.
- Packed format (`scripts/repack_lora_bank.py`, DEST `azeeer/eagle3-qwen3-8b-lora-bank-r32-packed-v1`, lines 25-26): per run `releases/<rel>/<cat>/<subset>/seed-N/` contains `epoch-NN.safetensors` (all snapshots of one collection epoch; tensor key `<snapshot_id>/<original PEFT key>`; metadata `format=speculators-packed-lora-epoch v1`), `manifest.json` (`format=speculators-packed-lora-run`, snapshot->tensor_keys map, source identity, adapter_config), `provenance.tar`, `recovery.tar` (uncompressed tars); top-level `catalog.json` (`speculators-packed-lora-bank`). Purely a storage repack to cut file count; no speculators import required.
- Port relevance: bank training uses the EAGLE-3 trainer path (`speculator_type: eagle3`, `bank/workflow.py:415`); LoRA bank is **not needed** for the direct-only campaign and a DFlash port can skip it.

## 6. Online vs offline activations

- **Online (current)**: `OnlineActivations` (`online_activations.py:61-304`) calls the vLLM OpenAI endpoint with `generate_hidden_states(client, model, {"input_ids": tokens})` (`data_generation/vllm_client.py`); vLLM's file-backend KV/hidden-state connector (`hs_connectors/`, filesystem backend) writes a safetensors file `{token_ids, hidden_states[seq, n_layers, 4096]}` under `online.shared_dir` (default `/tmp/speculators-online`; trainer and server must share the same absolute path/filesystem); trainer waits on a `.lock`, `safetensors.load(path.read_bytes())`, validates token ids/finite/shape (`n_layers == len(layer_ids)`)/width/dtype, then **deletes the file** (`online_activations.py:111-170`). Full payloads (prompt + response) go into a byte-bounded CPU LRU `ActivationRAM` (validation entries evicted last; `ram_cache_gib` 96/120) (`online_activations.py:27-58`); prompt summaries (last-prompt-token vector, 12288-d float32) are kept in RAM plus per-subset persistent matrices under `online.summary_cache_dir` (`persistent_summaries.py`) and are prepared for ALL train+val rows of the job's subsets before training (`campaign_online.md:131-138`).
  - Look-ahead: `lookahead_updates` (default 2), `buffered_examples` (64; 256 in 100K recipe), extraction `concurrency` (16; 128 in 100K recipe). Sampling/optimizer order unchanged by prefetch.
  - Memory/compute/disk: documented A100 80GB setup: vLLM `--gpu-memory-utilization 0.40`, `--max-num-seqs 16` (128 in 100K), `--enforce-eager`, no prefix cache/chunked prefill, `--max-model-len 8193`; training gets remaining ~48 GB. Host RAM: 64 GB planned originally; the 96-120 GiB RAM cache + 64x256 MiB buffer + summaries needs >=~160 GB host RAM for the shipped configs; observed trainer RSS 69.7 GB with cache at 63.97 GiB (`eagle3_activation_ram_cache.md:20-27`). Disk: local SSD for `/tmp` shared dir (transient, <= buffered_examples x 256 MiB), summaries, compiler cache, checkpoints (generator checkpoint.pt ~3.5 GB incl. Adam). 100K example: 2 x 96GB GPUs, first GPU vLLM, second trainer (`attention_100k_2k_v1/README.md`, tuned suggestion `--gpu-memory-utilization 0.70 --max-num-batched-tokens 16386 --lookahead-updates 8`, "not measured on the cluster").
  - GPU count: strictly one trainer process (`n_workers == 1` enforced, `campaign_config.py:130`); no DDP in generator training; bank training supports single GPU or replicated DDP (`execution.processes`), no FSDP. Multi-node only for *response generation* (`--num-machines/--machine-index`, flattened chunk index modulo machines, `nemotron_100k_v1/README.md:69-131`). The Mooncake hidden-state backend exists upstream in `hs_connectors/` but is not used by any fork code path (grep: only `scripts/benchmark.py` mentions it).
  - Colab/Drive assumptions: `/content/drive/MyDrive/...` appears only in READMEs, `generator_math.yaml:3`, `attention_24k_6k_v1/train.yaml`, and the `*_lora.sh` Colab scripts (outputs/checkpoints); training scratch is `/tmp` (hard-coded defaults, `campaign_config.py:45,73`, `config.py:127`). `os.sysconf` use in `feedback_execution.py:9` and `/tmp` defaults mean the code is Linux-only (use WSL locally).
- **Offline/hub (retired for training but still the default `activation_source: hub`, `campaign_config.py:66`)**: activations pre-extracted per row as `hs_<i>.safetensors` ("raw") or 1 GiB shards ("sharded") in `azeeer/eagle3-qwen3-8b-activations-v1`, indexed by `index.json` (`row -> shard`), fetched on demand into a checksum-verified LRU cache of up to 350 GiB (`campaign_cache.py`, `bank/hub_cache.py`, `bank/transfer.py`, `activation_cache.py`). Estimate in repo: ~1.57 TiB at 2K tokens avg, ~6.45 TiB at 8192 tokens for the whole expanded pool (`eagle3_generator_scaleup.md:243-244`, "estimates, not measured").
- **Backbone**: HF `transformers` forward is NOT used for the target; the target is always vLLM (hidden states at layers `2,18,33` + final). The frozen drafter + generator run in the trainer process via PyTorch (FlexAttention); the verifier head/norm tensors are loaded from the local target dir (`engine.py:79` "frozen EAGLE3 and verifier head/norm").
- Local 8 GB RTX 4060: Qwen3-8B BF16 (~16 GB) cannot be served by vLLM there; only the synthetic CPU/GPU `tiny_campaign` fixtures (`tests/unit/generator/test_campaign.py`, `test_online_campaign.py:1,28-33` "real tiny training"; `device: cpu` hint at `engine.py:62`) are feasible. A DFlash smoke test would need a tiny Qwen3-like target + tiny drafter + synthetic trajectories (UNVERIFIED that existing tiny fixture builds a DFlash-compatible model; it builds EAGLE-3).

## 8. Drafter-agnostic vs EAGLE-3-specific; DFlash port implications
